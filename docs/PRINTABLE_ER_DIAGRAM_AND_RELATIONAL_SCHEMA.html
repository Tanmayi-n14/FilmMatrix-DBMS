2. Formal Relational Schema Specification (Underlined PKs, FK* Notations)

Standard relational algebra representation satisfying Third Normal Form (3NF / BCNF). Primary keys are underlined; foreign keys are designated with asterisks (*).

1. Movies (movie_id, title, release_year, box_office_earnings, synopsis, studio_id*, created_at)
    Constraints: release_year >= 1888, box_office_earnings >= 0.00

2. ProductionBudgets (budget_id, movie_id*, production_cost, marketing_spend, currency)
    Constraints: UNIQUE(movie_id), production_cost >= 0.00, marketing_spend >= 0.00

3. Actors (actor_id, name, birth_year, nationality, oscar_nominations, biography)
    Constraints: birth_year >= 1850, oscar_nominations >= 0

4. MovieCast (cast_id, movie_id*, actor_id*, character_name, billing_order)
    Constraints: UNIQUE(movie_id, actor_id), billing_order >= 1

5. Directors (director_id, name, nationality, birth_year)
    Constraints: name NOT NULL, birth_year >= 1850

6. MovieDirectors (movie_id*, director_id*, is_primary_director)
    Constraints: Composite PK (movie_id, director_id)

7. Genres (genre_id, genre_name, description)
    Constraints: UNIQUE(genre_name)

8. MovieGenres (movie_id*, genre_id*)
    Constraints: Composite PK (movie_id, genre_id)

9. Studios (studio_id, studio_name, headquarters, founded_year)
    Constraints: UNIQUE(studio_name), founded_year >= 1880

10. Users (user_id, username, email, role, password_hash, created_at)
    Constraints: UNIQUE(username), UNIQUE(email), role IN ('Admin', 'Viewer', 'Critic')

11. Watchlists (watchlist_id, user_id*, movie_id*, added_at)
    Constraints: Compound UNIQUE(user_id, movie_id) (prevents duplicate bookmarks)

12. WatchlistActivityLogs (log_id, watchlist_id*, user_id*, movie_id*, action_type, details, logged_at)
    Constraints: Immutable audit trail populated exclusively by MySQL Triggers

13. Reviews (review_id, user_id*, movie_id*, rating, review_text, reviewed_at)
    Constraints: rating BETWEEN 1.0 AND 10.0, UNIQUE(user_id, movie_id)

14. Awards (award_id, movie_id*, award_name, category, award_year, is_winner)
    Constraints: award_year >= 1920

3. Academic 3NF Normalization Proof & Functional Dependencies

• First Normal Form (1NF): All table attributes contain strictly atomic, scalar values. Repeating groups and multi-valued attributes (e.g. multiple genres or actors per movie) have been systematically decomposed into dedicated bridge relations (MovieGenres and MovieCast).

• Second Normal Form (2NF): Schema satisfies 1NF, and every non-prime attribute is fully functionally dependent on the entire primary key. In compound key relations such as MovieCast(movie_id, actor_id), the non-prime attribute character_name depends on the combination of both the film and the actor, exhibiting zero partial functional dependencies.

• Third Normal Form (3NF): Schema satisfies 2NF, and there are zero transitive functional dependencies ($X \rightarrow Y$ and $Y \rightarrow Z$ where $Z$ is non-prime). Studio metadata resides exclusively in Studios, filmmaker biographies in Directors, and financial ledgers in ProductionBudgets, completely eliminating update, insertion, and deletion anomalies.
